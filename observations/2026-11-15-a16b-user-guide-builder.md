# Зауваження: A-16b (user-guide-builder 0.4.0), перший запуск на стенді A-15-full (2026-11-15)

- Скіл: `flow-package-build:user-guide-builder` 0.4.0 (`scripts/check_guides.py`, `scripts/shoot.mjs`).
- **Розмір кадру.** `shoot.mjs` знімає з viewport 1440×810 і без `deviceScaleFactor`; вимога сесії/власника — 1440×900, DSF 1. Сесія знімала копією
  логіки скрипта з цими параметрами (AI-17). Пропозиція: параметри `viewport`/`dsf` у `shoot-plan.json`.
- **Часовий пояс першого входу.** Chromium з `timezoneId: Europe/Kyiv` повідомляє `Europe/Kiev`; Odoo при першому вході демо-користувача записує цей
  пояс (`res_users._login`, cookie `tz`), PostgreSQL стенда назви `Europe/Kiev` не знає → графік «Завантаження дільниць» (групування за тижнем) падає.
  Сесія після входу повертала `Europe/Kyiv` (AI-18). Пропозиція: у `shoot.mjs` (і в турах A-16) після входу скидати пояс користувача або ставити
  `login_date` демо-ролям у `td_mebli_demo`; для клієнтів — перевірка `pg_timezone_names` у B-04.
- **Дії-майстри за прямою адресою.** `/odoo/action-<майстер>` (напр. `td_mebli_mrp.td_mebli_spec_import_action`) без контексту дає діалог помилки;
  `shoot-plan.json` має вести через кнопку на формі. Пропозиція: у `references/screenshots.md` — правило «майстри знімати через кнопку-джерело».
- **UG-cover-dev — лише меню/дії/звіти.** Кнопки заголовка форм, поля `res.config.settings`, розклади, шаблони листів, групи, правила, нумерація, елементи
  навбару (JS) скрипт не збирає; таблицю «розроблене» сесія зібрала з бази стенда (XML-RPC) — 308 рядків проти 63 у скрипті (AI-19). Пропозиція:
  опційний вхід `--inventory <json>` (вивантаження з бази) для UG-cover-dev.
- **Серверна дія меню «Мій день».** Адреса дії вікна `td_mebli_install_day_action` показує всі виїзди (110), меню веде через серверну дію з фільтром
  дня — у плані зйомки треба брати дію меню, а не вікна.
