## Діагностика туру `td_mebli_sale_configurator_tour` (повний профіль)

Відтворено `odoo-bin --test-tags /td_mebli_sale:TestConfiguratorTour` на `demo-mebli-pkg-a` (лог і скріншоти — scratchpad), три послідовні причини;
кожну наступну видно після обходу попередньої в тестовій базі (SQL-правки лише для діагностики, стенд скинуто зі знімка):
1. **Крок 4/18 `.o_sale_order` (TIMEOUT).** Кореневе меню «Продажі» без дії — веб-клієнт відкриває перший дочірній пункт. `td_mebli_measure`
   додає «Замір-листи» з `sequence="3"` у `sale.sale_order_menu` (`td_mebli_measure/views/measure_views.xml:178-179`, «Календар замірів» —
   `:239-240`, `sequence="4"`) перед стандартними «Комерційні пропозиції» (`sequence="10"`) → застосунок відкриває список `td.mebli.measure`
   (лог: `td.mebli.measure/get_views` після кліку). Після `sequence=50` крок 4 проходить. На мінімальній базі `td_mebli_measure` немає.
   Причина в тесті (тур спирається на неявну стартову дію застосунку) + побічна зміна UX пакета (менеджер у «Продажах» бачить спершу заміри — у SPEC цього немає).
2. **Крок 8/18 `a:contains("Add a product")`.** Мова admin на повному профілі — `uk_UA` (установка з `uk_UA`, `td_mebli_demo/showcase.py:320`),
   стандартні кроки `sale/static/src/js/tours/tour_utils.js` шукають англійський текст. Після `lang=en_US` у тестовій базі тур доходить до кроку 18.
   Причина в тесті (HttpCase не фіксує мову користувача).
3. **Крок 18/18 «wait for save completion».** `web_save` відхилено: «The stage follows the production: only moving a waiting order to «In production» is possible.»
   Це дефект пакета D-02 (не тесту): форма нового замовлення не зберігається в UI взагалі.
JS-помилок у консолі немає; права admin не причина. Код повернення — **A-11** (D-02 — модуль, D-15 — тест у `package/addons/td_mebli_sale/tests`).
