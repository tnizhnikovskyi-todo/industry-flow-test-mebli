# Мости EE (коробка C)

**Статус: контракт, не звірений з кодом EE.** Доступу до бази й коду Odoo 19 Enterprise немає (AI-11, ВП-4); технічні назви EE-модулів — з заглушок CE `odoo/addons/base/data/ir_module_module.xml` (`mrp_workorder` :257, `quality_control` :131, `industry_fsm` :61, `planning` :159, `helpdesk` :75, `sign` :187 — номери рядків за PLAN.md §2). Поля й методи EE-моделей нижче — **припущення до звірки в A-11** (AI-A08-18). AC: AC-113, AC-126…AC-130.

**Правило співіснування (BOX §12, G-73):** на EE головний запис кроку — у стандартному додатку; міст зв'язує його із замовленням і нашими даними; наш екран для цього кроку ховається групою; дані `td_` лишаються для історії й звітів. Кожен міст: `depends` = модуль ядра + EE-додаток, `auto_install: True`, ліцензія LGPL-3 (наш код), без копіювання коду EE.

| Міст | `depends` | Головний запис на EE | Що робить міст | Що ховається | Перенесення даних при апгрейді CE → EE |
|---|---|---|---|---|---|
| `td_mebli_shopfloor` | `td_mebli_shop`, `mrp_workorder` | робоче завдання Shop Floor | показ деталей (`td_part_ids`) і причин паузи в Shop Floor; працівник рядка часу — з EE | меню й кнопки планшета `td_`, `group_feature_kiosk` знімається | `mrp.workcenter.productivity.td_employee_id` → поле працівника EE [перевірити] |
| `td_mebli_quality` | `td_mebli_shop`, `quality_control` | перевірка Quality | точки якості з `td_quality_point` операцій → точки Quality; журнал невідповідностей для дашборда — з Quality | `td.mebli.quality.check` UI | історичні перевірки — лишаються в `td_`, дашборд читає обидва джерела |
| `td_mebli_fsm` | `td_mebli_install`, `industry_fsm` | задача Field Service | акт `td.mebli.install.act` і % бригаді прив'язані до задачі FSM (на EE їх немає); денний план — з FSM | календар монтажів `td_` | задачі проєкту монтажів → проєкт FSM [перевірити] |
| `td_mebli_planning` | `td_mebli_install`, `planning` | зміна Planning | графік бригад — у Planning (Гант) | календар бригад `td_` | — |
| `td_mebli_helpdesk` | `td_mebli_claim`, `helpdesk` | тікет Helpdesk | тікет ↔ замовлення, деталь, рекламація (`repair.order`); «Повторне виготовлення» з тікета | канбан рекламацій `td_` | відкриті рекламації лишаються в `repair` |
| `td_mebli_sign` | `td_mebli_install`, `sign` | запит Sign | PDF договору й акта (наші шаблони) → запит Sign; підписаний файл — у чат замовлення / акта | кнопки підпису порталом для договору | — |

**CI (C-03):** матриця CE + ядро; EE + ядро без мостів; EE + ядро + мости — мости тестуються лише в третій (BOX §12). AC-130 — інсталяція CE без мостів і без помилок залежностей.
**Ліцензування EE:** робітники цеху в Shop Floor і монтажники — Light User або повні (AI-01) — не технічне питання ТР.
