## 3. Невідповідності документів і коду (виправити)
- Оптимізатор розкрою є в коді (`td_mebli_cutting/models/optimizer.py`, `sheet_map.py`), а REJ-020 — «ніколи»; картка «Відхід розкрою» показує «Імітація».
- PLAN §3: `td_mebli_cost` — залежності й «адаптований REUSE-01» не збігаються з кодом (залежить лише від `td_mebli_sale`, факт — огляд МО, не аналітика); модуля `td_mebli_bas` немає (обмін — `td_mebli_ua`).
- F-45: у концепції 12 показників, у зрізі 11 (рядок якості — B), а BOX §1 дає A «дашборд повністю».
- F-43/F-44: підпис версії зміни клієнтом — у README зараховано, у PLAN — «B, не в зрізі».
- F-25, F-29, F-46: у README «Відкинуто», а в complexity — рівень «код».
- F-01: «Excel» обіцяно в A, код читає лише CSV; статус імітації різний у complexity / PLAN.
- README: кількість кадрів у §3, §7, §12 різна. SALES §6 колонка «у зрізі» застаріла.
- Зріз показує обсяг коробки B (кіоск за PIN, якість, обрізки, пакет розкрою); окремого показу складу A немає.

## 4. Рекомендація
1. Перед ТР: доробити в зрізі A1–A4 (код у межах коробки A) і виправити §3 (документи й оптимізатор).
2. Паралельно запустити зовнішні рішення B1, B2, B5 (франчайзі, юрист, зразки CAD); B3, B4 — рішення AI з ризиком (власник — вето).
3. C1–C7 і D1–D4 — у ТР (A-08): архітектура й «не робимо».
4. Після цього ТР коротким SPEC (AC з треками) — більша частина дизайну вже в зрізі.
